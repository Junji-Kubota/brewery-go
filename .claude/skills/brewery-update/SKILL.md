# Brewery GO データ更新

`data/places.js` の店データを、Web で調べて追加・修正する手順。

## 基本ルール
- 対象は醸造所（ブルーパブ含む）と、地元のクラフトビールを扱う酒屋。仕入れて出すだけのビアバーは入れない
- 情報は必ず公式サイト・公式SNS・自治体・観光協会など出典のあるページで確認する。推測で埋めない
- 確認できなかった項目は `null` のままにし、`note` に理由を書く（例:「タップルームなし。出荷のみ」）
- 更新した店には `checked:"YYYY-MM-DD"` を付ける。`src` は実際に確認したページにする
- 既存の `id` は変えない（ユーザーの「飲んだ」記録が id に紐づいている）

## 項目の書き方
- `h`（営業時間）: `"火-金15:00-23:00;土日12:00-22:00"`
  - 曜日は 日月火水木金土。範囲は `火-金`、飛び石は `月水金`
  - 1日に複数の枠があるときは `,` で区切る: `月-金11:30-15:00,17:00-22:00`
  - 深夜0時を越える場合は `18:00-24:00` のように24時までで止める
  - 定休日は書かない（書いていない曜日が休み）。「第4火曜休み」などは `note` へ
  - タップルームや直売所がなく、飲めない・買えない醸造所は `h:null` にして `note` に「一般営業なし」、`service:"shipping"` を付ける
- `service`: `"shipping"` は出荷専用（その場で飲めない・買えない）醸造所。アプリでは灰色の小さいマークになり、「飲める店だけ」の絞り込み（最初はオン）で隠れる
  - 付けるのは、公式などで「タップルーム・直売なし」と確かめられたか、住所が事務所や工場だけで店舗営業が見当たらない場合
  - 別の場所にタップルームがある場合も、そのエントリの住所で飲めなければ付け、`note` にタップルームの場所を書く
  - 出荷専用の店に `h` は書かない（validate.py が NG にする）
  - 店舗営業があるのに時間が分からないだけの店には付けない（`h:null` のまま「要確認」）
- `founded`: 醸造所の開業（醸造開始）年。前身や親会社の創業年は `foundNote` に書く
- `awards`: 直近の審査会の受賞数 `{c:"JGBA",g:金,s:銀,b:銅}`。c は JGBA / IBC / WBC のいずれか
- `guide:true`: ビアEXPO2025 出展203社（`data/guide203.csv`）に載っている醸造所
- `yomi`: 英語名の店はひらがなの読みを入れる（検索用）
- `bulk:true`: 一括登録した未確認の店。個別に調べて営業時間などを確認したら `bulk` を消し、`checked` と `src` を確認したページに更新する

## 位置（緯度経度）の調べ方
国土地理院の住所検索APIを使う（無料・キー不要）。

```
curl "https://msearch.gsi.go.jp/address-search/AddressSearch?q=東京都三鷹市下連雀4-1-16"
```

結果の `geometry.coordinates` は `[経度, 緯度]` の順なので、`lat` と `lng` を取り違えないこと。
番地まで出ないときは町名の位置を使い、`note` に「位置は○○の目安」と書く。

## 作業の流れ
1. `python tools/validate.py` で現状を確認する
2. 対象の店を1軒ずつ調べ、`data/places.js` を編集する（まとめて10軒程度ごとに区切る）
3. 編集のたびに `python tools/validate.py` を実行し、NG がないことを確認する
4. 変わった内容を一覧でユーザーに報告する（追加・修正・閉店の疑い・確認できなかった店）
5. ユーザーの確認後に commit し、push する（push すると GitHub Pages に反映される）

## 閉店の扱い
公式に閉店が発表されていれば削除せず `closed:true` と `note` を付けてユーザーに報告する。
判断がつかないものは「閉店の疑い」として報告だけする。
